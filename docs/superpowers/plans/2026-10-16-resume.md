# Resume Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `/resume/` page in the "three numbers, then proof" direction, plus a matching one-page `public/resume.pdf` printed from it.

**Architecture:** Content lives in `src/content/resume.ts` and reuses existing modules where a number already exists. A server-rendered page uses `HonestText` for the band captions. A print stylesheet turns the same page into an A4 single column. `scripts/resume-pdf.mjs` serves `out/` and calls headless Chrome's `--print-to-pdf`.

**Tech Stack:** Next.js 16 static export, React 19, Tailwind 4, Vitest. Headless Chrome is already installed locally, so no new dependency is needed.

**Spec:** `docs/superpowers/specs/2026-10-16-resume-design.md`

## Global Constraints

- Never use em dashes. `content.test.ts` enforces this for every module listed in its `modules` map, so register `resume` there.
- Every `LinePair` must keep its honest line within 25% of the polished line's length (`LINE_LENGTH_TOLERANCE`).
- WhatsApp link: `https://wa.me/919380654730`. The number is shown as text in print: `+91 93806 54730`.
- Copy says "flows I built", never "sold". PRs are "governed". Cold Stone is "launching". There is no E3 booking count and no client-launch count.
- Search title is 65 characters or fewer.
- No AI attribution anywhere. Branch, then PR, then merge. Update `docs/STATUS.md` in the same PR.

## Review Focus

- **Printing the page**: the nav, footer, lens disc, toggle buttons and the "PDF" button must not print, and the honest overlay must never print.
- **PDF text extraction**: "70,000+" must come out as one token. This is why the resume does not use the odometer, whose digit columns would extract as noise.
- **Phone width (375px)**: the band stacks and nothing scrolls sideways.
- **Reduced motion**: the page has no motion that ignores `prefers-reduced-motion`.
- **The contact card**: it must be a real link that keyboard users can reach, with a separate link to the PDF.

### Task 3: PDF generation

**Files:**
- Create: `scripts/resume-pdf.mjs`, `public/resume.pdf`
- Modify: `package.json`, adding the script `"resume:pdf": "node scripts/resume-pdf.mjs"`
- Test: `src/content/resume-pdf.test.ts`

The script:
- Serves `out/` on a free port with `node:http`, respecting the trailing-slash index files.
- Runs Chrome from `CHROME_PATH`, falling back to the standard Windows, macOS and Linux paths, with `--headless=new --disable-gpu --no-pdf-header-footer --print-to-pdf=public/resume.pdf --virtual-time-budget=5000 http://127.0.0.1:PORT/resume/`.
- Exits non-zero if the file is missing.

- [ ] Write `resume-pdf.test.ts`. It is skipped when `pdftotext` is not on PATH.

  - Assert that the output contains `70,000+`, `Experience`, `rigan@verastack.dev` and `+91 93806 54730`.
  - Assert that the PDF has exactly 1 page, using `pdfinfo` if present, or by counting `/Type /Page` objects with a regex: `/\/Type\s*\/Page[^s]/g`.
- [ ] Run `npm run build && npm run resume:pdf`, then run the test. If it reports 2 pages, apply the spec's cut order in print CSS only: coaching line, then the press line down to Autocar India, then the freelance row down to one line.
